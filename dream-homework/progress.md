## 이어서 할 때 주의 사항

### 사용자(사람)에 대해
- **코딩 초보자.** 설명은 쉽고 짧게, "어느 파일을 왜 바꿨는지" 적기. **수정한 파일은 일부가 아니라 전체 코드**로 줄 것(GitHub에 그대로 덮어쓰기 위해). 새 파일은 "새로 올릴 것", 지울 파일은 "지울 것"으로 명확히.
- 컴퓨터 폴더에서 먼저 확인하고 GitHub에 올림. GitHub에는 `dream-homework` 폴더 **안에** 올려야 하며, 엉뚱한 폴더에 올리면 덮어쓰기가 안 됨(한 번 겪음). `assets` 폴더는 `index.html`과 같은 위치.
- 일부 파일만 덮어쓰면 화면이 비거나 오류 상자가 뜸. 확실한 방법은 `js` 폴더 통째 교체.
- 토큰 절약을 위해 **작업 하나가 끝나면 새 채팅**을 쓰는 편. 새 채팅에는 `progress.md`, `DESIGN.md`, `HANDOFF.md`와 고칠 파일만 올리게 안내.
- 메시지는 맞춤법이 흔들리는 경우가 많음("쟤료"=재료, "절때"=절대 등). 아래 "확인할 것" 참고.

### 코드 규칙 (어기면 오류가 남)
- 모든 `js`는 일반 `<script>`로 **같은 전역 공간을 공유**함. `import/export` 금지. **같은 이름의 `const/let/function`이 두 파일에 있으면 오류** → 새 이름을 쓰기 전에 검색할 것(중복 선언 검사를 해 왔음).
- **`index.html`의 `<script>` 순서를 바꾸지 말 것.** 새 파일은 알맞은 자리에 한 줄 추가(`14-main.js`는 항상 마지막).
- **파일 버전 검사**: 각 파일에 `const BUILD_xx = 숫자;`가 있고, `index.html`의 `NEED` 표에 `파일: [변수이름, 최소 버전]`이 있음. 파일을 크게 고치면 그 파일의 숫자와 `NEED`의 숫자를 같이 올리고 `index.html` 탭 제목 버전도 올릴 것. **새 파일을 만들면 `NEED`에도 넣을 것.** 지금 바뀐 파일은 41, `06`, `07b`, `09`, `14`는 40.
- 일시정지는 `quizOpen = true`를 재사용(노트, 인벤토리, 퀴즈 등). 새 팝업도 이 방식.
- 새 `gameState`를 만들면 `05-input.js`(입력), `12-update.js`(update), `13-render.js`(draw) **세 곳**에 처리 추가.
- 새 상호작용 오브젝트는 `12-update.js`의 `INTERACTABLE_TYPES`/`isInteractableNow`, `07`의 `interactWith`, `13`의 그리기 분기 **세 곳**에 같이(그리기를 빼먹으면 빨간 적 모양으로 나옴).
- 방 번호/문 위치를 바꾸면 `03`(상수), `10`(연결 규칙), `11`(`crossRoom`, 카메라), `12`, `13`(그리기/미리보기)이 서로 연결돼 있으니 같이 확인. 방 이동 시 방의 적 위치를 먼저 계산(`crossRoom`의 `placeEnemyForFrame`) — 안 하면 처음 가는 방에서 플레이어가 튕겨 나가는 문제가 있었음.
- 히든방 입구 카메라 고정은 `camLocked` + `camEaseOffset`으로 튀지 않게 풀림. 미리보기 카메라(`camXAfterCrossing`)와 실제 카메라(`currentCamX`) 규칙은 같아야 함.
- **블러는 `ctx.filter`를 쓰지 말 것**(아이폰에서 안 먹음). 그림은 `getImageData`로 읽지 말 것(컴퓨터에서 파일을 직접 열면 막힘, 지금은 `source-atop`으로 색칠한 복사본을 씀).
- 문구/주석은 쉬운 한국어로. 큰 수치는 파일 맨 위 상수로 빼서 사람이 고치기 쉽게.
- 작업을 끝내면 `DESIGN.md`(기준), `HANDOFF.md`(맨 위에 기록 추가), `CHANGELOG.md`, `README.md`(조작이 바뀌었을 때)를 같이 갱신.

## 스토리

> 사람이 정한 큰 틀(초안). 자세한 버전은 `DESIGN.md`의 "스토리 틀". **구현된 것(✔)과 아직 없는 것(✘)** 표시.

**진행 순서**
1. 초반 스토리 → 방향키 해금 → 첫 번째 방(히든 연구실) 도착 ✔
2. 첫 번째 방: **연구 노트**(히든 루트의 떡밥 + 메인 루트의 연구 일기), **쪽지**(무언가를 만들 재료 = **노멀 엔딩의 최종 열쇠**) ✔(글은 임시)
3. 두 번째 방: **무기 만드는 방법의 서류 뭉치**(인벤토리에서 상시 확인), 망치는 무기 제작 재료 ✘(제작 시스템 설계 중, 위 10번)
4. 세 번째 방부터: 주인공이 이 공간에 있는 **진짜 이유**가 서서히 밝혀짐(어느 기계에서 인체 실험을 한 흔적) ✘
5. **3번째 방에서 2번째 방으로 넘어가는 이상 증세** ✘ (이번 요청: 3번 히든방에서 2번 히든방으로 자연스럽게 가는 연결부터)
6. 4번째 방쯤에서 재료를 다 모으면 출구에서 쪽지대로 만든 것을 사용 ✘

**엔딩 (인벤토리 "엔딩 카드"에 모임. 지금은 카드 4장만 있고 얻는 조건은 코드에 없음. `unlockEnding('id')`로 채움)**
- **노멀 A** (`normalA`): 3번째 방 → 2번째 방을 **3번 이상** 넘어간 뒤 **무기로 스스로 죽음을 택하면**, 몸에 손상을 입고 장애를 가진 채 탈출. (스스로 죽는 방법은 따로 만들 것)
- **노멀 B** (`normalB`): 출구에서 쪽지대로 만든 것으로 행동 → **졸음 스택이 1000을 뚫고 걷잡을 수 없이 올라가다가 바가 깨짐** → 마지막은 영원히 실험관에서 잠든 모습.
- **트루 = 해피** (`true`): **아무도 죽이지 않고**, **무기를 가진 채**, **다른 이동 방법을 가진 노란 선**을 무기로 파괴 → 끝으로 가지 못하게 계속 뒤로 보내던 몬스터는 **주인공의 맨정신의 일부**라서 죽이면 정상 생활이 안 됨(그래서 죽이면 안 됨) → 탈출해 빛나는 출구로 나가면 **교수와 일당은 붙잡히고** 주인공은 해피 엔딩. (트루와 해피는 같은 엔딩으로 이해함)
- **히든** (`hidden`): 실험 자체가 붕괴하는 느낌. 조건 미정(히든 루트).
- 규칙: 적을 **무기로 한 번이라도 죽이면 트루 엔딩 불가**(`gameStats.kills`로 세는 중). **투사체를 부수는 건 죽인 것으로 세지 않음.** 이를 암시하는 **힌트를 곳곳에 뿌릴 것** ✘.
- 졸음 스택은 **일부러 줄지 않음**(노멀 B의 폭주 연출이 이 스택을 씀).

**아직 정해지지 않은 것**: 노란 선의 위치와 정체, 스스로 죽는 방법, 히든 엔딩 조건, 3번째 방 이후의 맵/연출, 무기 제작의 세부(부품 이름/재료), 연구 노트·서류의 실제 글, 이상 증세(방 이동) 연출.
