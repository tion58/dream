# 꿈속의 과제 (Dream Homework) - 프로젝트 정리 문서

> 이 문서는 사람과 AI(Claude, Gemini 등)가 같은 내용을 보고 작업하기 위한 기준 문서입니다.
> **AI는 작업을 시작하기 전에 이 문서를 먼저 읽고, 아래 "결정된 사항"을 바꾸지 않은 채 작업해 주세요.**
> 현재 기준 버전: 프로토타입 v38 (파일 분리 완료)

## 1. 프로젝트 개요

- **장르**: 도트(픽셀아트) 스타일 2D 퍼즐 + 회피 액션 (브라우저 게임)
- **스토리**: 과제를 하다가 너무 졸려서 잠이 들고, 꿈속 게임 세계에 오게 된다. 과제를 해야 하니 잠에서 깨야 한다. (스토리의 큰 틀과 엔딩은 바로 아래 "스토리 틀 (초안)" 참고)
- **핵심 컨셉**: 처음에는 이동 키가 대부분 잠겨 있고, 문제를 풀거나 맵을 진행하면서 능력(방향키)을 하나씩 해금해 나간다.
- **분위기**: 핑크색 구름 느낌. 스테이지를 진행할수록 배경이 점점 어두워진다(낮 → 노을 → 밤 직전). 히든방은 검은색~남색.
- **기술**: HTML + CSS + JavaScript(Canvas 2D). 외부 라이브러리 없음, 빌드 과정 없음(파일 그대로 브라우저에서 열림). 효과음은 Web Audio API로 직접 합성(음원 파일 없음). 코드는 `index.html` / `style.css` / `js/` 폴더로 나뉘어 있다(아래 3번 참고).
- **배포 계획**: GitHub 저장소 + Netlify(정적 호스팅)
- **개발자 수준**: 코딩 경험이 거의 없는 초보자 → 설명은 쉽게, 변경 사항은 어디를 왜 바꿨는지 짧게 적어 주세요.

### 스토리 틀 (초안: 사람이 정한 큰 흐름)
아래는 사람이 정리한 틀이다. **구현된 것과 아직 안 된 것을 구분해서 적었다.** 세부 내용은 작업을 시작할 때 사람과 정할 것.

**진행 순서**
1. 초반 스토리 → 방향키 해금 → 첫 번째 방(히든 연구실) 도착 *(구현됨)*
2. 첫 번째 방: **연구 노트**에서 히든 루트의 떡밥과 메인 루트의 연구 일기를 알게 되고, **쪽지**에서 무언가를 만들 재료를 알게 된다. 이 재료가 **노멀 엔딩의 최종 열쇠**다. *(노트/쪽지/용기는 있음, 내용은 임시)*
3. 두 번째 방: **무기를 만드는 방법이 적힌 서류 뭉치**(인벤토리에서 언제든 다시 볼 수 있음). 망치는 무기를 만들 때 필요한 재료다. *(아직 없음. 무기는 지금 임시로 히든방1 바닥에 놓여 있음)*
4. 세 번째 방부터: 주인공이 이 공간에 있는 진짜 이유가 서서히 밝혀진다. 어느 기계에서 **인체 실험을 한 흔적**이 보인다. *(아직 없음)*
5. 세 번째 방에서 두 번째 방으로 넘어가는 이상 증세가 나타난다. *(아직 없음. "3번째 히든방 → 2번째 히든방 순간이동"도 구상만 있고 **구현하지 않음**)*

**엔딩 (인벤토리의 "엔딩 카드"에 모임. 얻지 못한 것은 빈 칸. 카드 글은 임시)**
- **노멀 엔딩 A**: 3번째 방에서 2번째 방으로 **3번 이상** 넘어간 뒤, 무기로 **스스로 죽음을 택하면** 몸에 손상을 입고 장애를 가진 채 탈출한다. *(v47 구현: 히든방3에 20초 있으면 이상 증세로 히든방2 맨 위 방으로 되돌아감. 3번 이상 되돌아온 뒤 선택지가 뜨고, 무기를 가지고 "스스로 이 꿈을 끝낸다"를 고르면 A. 방법은 그리지 않고 선택지로만 처리. `12c-story-events.js`)*
- **노멀 엔딩 B** *(v47 구현: 사람이 재료를 정함 = 용기 + 약품(히든방3) + 찢어진 쪽지 + 전리품(적을 죽이면 나옴) → ■■ 제작 → 인벤토리에서 먹으면 폭주 → 졸음 바가 깨짐 → B)*: 4번째 방쯤에서 재료를 다 모으고, 출구에서 쪽지에 적힌 대로 만든 것을 써서 행동하면 **졸음 스택이 1000을 뚫고 걷잡을 수 없이 올라가다가 바가 깨진다.** 마지막은 영원히 실험관 속에서 잠든 모습.
- **트루 엔딩 (= 해피 엔딩으로 이해함)**: **아무도 죽이지 않고**, **무기를 가진 채**, **다른 이동 방법을 가진 노란 선**을 무기로 파괴하면 도달. 이유: 끝으로 가지 못하게 계속 뒤로 보내던 몬스터는 사실 **주인공의 맨정신의 일부**여서, 죽이면 정상적인 생활이 안 된다. 그래서 죽이지 않아야 한다. 탈출해 빛나는 출구로 나가면 연구를 한 **교수와 일당은 붙잡히고** 주인공은 해피 엔딩.
- **히든 엔딩**: 실험 자체가 붕괴하는 느낌 (조건은 미정. 히든 루트).
- 적을 **무기로 한 번이라도 죽이면** 트루 엔딩에 갈 수 없다(`gameStats.kills`로 세고 있음). **무기로 투사체를 부수는 건 "죽인 것"으로 세지 않는다.** 이를 암시하는 **힌트를 곳곳에 뿌릴 것** *(아직 없음)*.

**v44에서 대충 적용한 것(글은 모두 임시, `07d-dialogue.js` / `07b-reader.js`)**
- 설정(내가 정함): 교수가 "과제에 쫓기는 학생"을 피험자로 꿈 공간에 가두는 수면 실험. 감시자(몬스터)는 피험자의 맨정신 일부. 졸음 수치는 일부러 줄지 않게 설계됨. 출구는 열려 있지만 교수는 "아무도 못 나간다"고 적어 둠.
- 연구 노트(히든방1): 연구 일기 3쪽 + 찢긴 뒷장(검은 통로 떡밥). 서류 뭉치(히든방2 방4): 도구 만드는 법(v45에서 "감시자를 해칠 필요는 없다" 문구는 뺌). 작업 일지(히든방3). 실험 기록(히든방4): 인체 실험 흔적.
- 게임 중 **대사창**(주인공 혼잣말): 히든방1~4/방2 처음 진입, 첫 무기 제작, 처음 적을 죽였을 때(찝찝함 = 트루 힌트), 3→2 되돌아오기 3번, 졸음 500/900.
- (v46에서 맵 탈출구를 없애 이 결말은 지금 쓰이지 않음) 마지막 출구(오른쪽 벽 위)의 결말: **트루 카드는 임시로 "아무도 안 죽이고 무기를 가진 채 도착"일 때** 줌(노란 선 파괴가 정해지면 교체). 적을 죽였으면 카드 없는 "뭔가 빠진 느낌" 결말, 무기가 없으면 카드 없는 평범한 결말.
- 노멀 A/B, 히든은 조건이 없어서 카드를 주지 않음(3→2 이동 횟수만 `gameStats.backCount`로 셈).

**아직 정해지지 않은 것**: 노란 선의 위치와 정체, 스스로 죽는 방법, 히든 엔딩 조건, 3번째 방부터의 맵과 연출, 무기 제작법과 재료, 연구 노트/서류의 실제 글, 이상 증세(방 이동) 연출.

## 2. 지금까지 구현된 것 (v48 기준)

### 화면 흐름
1. 타이틀 화면(PLAY 버튼) → 2. 도입부 스토리(대화창, SKIP 버튼 있음) → 3. 본 게임
- 스토리 UI: 하단 대화창 + 이름칸, 캐릭터 그림 없음, 배경 있음, 좌상단 뒤로가기 / 우상단 설정·SKIP 버튼. SPACE 또는 클릭으로 진행.
- 설정 화면: ESC 키 또는 화면의 ⚙ 버튼. 화면 비율(16:9 / 4:3 / 21:9) 선택과 음향 볼륨 슬라이더가 있다.
- 세로 모드에서는 플레이할 수 없고 "가로로 돌려주세요" 안내가 뜬다.

### 이동과 조작
- **충전-발사 이동**: 방향키(또는 WASD)를 꾹 눌렀다 떼면 그 방향으로 발사되어 미끄러진다. 약 0.75초(45프레임)면 풀차징이고, 풀차징으로 발사하면 약 120픽셀을 미끄러진다. 아주 살짝 누르면 아주 조금만 나간다. 공격에 맞으면 충전이 취소된다.
- **방향키 개별 잠금**: 위/아래/왼쪽/오른쪽이 각각 잠겨 있다. 잠긴 방향은 화면 D패드에 🔒가 보이고, 해금되면 팝 애니메이션과 함께 화살표로 바뀐다.
- **시작 상태**: 처음에는 **아래쪽만** 열려 있다. 나머지 방향을 눌러도 처음에는 아무 반응이 없다. 튜토리얼 상자(아래 참고)를 발견한 뒤부터는 잠긴 방향을 누르면 "과제를 풀자" 수학 문제가 나오고, 풀면 그 방향이 해금된다. 문제를 푸는 동안 적과 투사체는 멈추고 새 피격은 무시된다(이미 진행 중이던 연쇄 피격만 유지).
- **시작 구역 자유 이동**: 방0 왼쪽의 **투명한 노란 점선(x=`FREE_ZONE_RIGHT`) 안쪽**에서는, **위/아래 방향키를 해금한 뒤**(왼쪽/오른쪽은 잠겨 있어도 됨, 해금한 방향으로만 움직임) 충전 없이 방향키를 누르는 동안 자유롭게 걸어다닐 수 있다(속도 `FREE_MOVE_SPEED`). 선 밖은 예전처럼 충전-발사. 노란선은 평소엔 조금 흐리고, 4개를 모두 해금하면 더 또렷해지며 그때 안내 메시지가 한 번 뜬다. (위/왼쪽/오른쪽 문제 3개를 모두 풀어야 4개가 해금됨)
- **상호작용 키**: E 키(모바일은 화면의 E 버튼). 가까이 가면 "E ○○" 안내가 뜬다(오브젝트마다 문구가 다름). **가까이에 상호작용할 것이 없을 때, 방패를 끼고 있으면 E를 누르고 있는 동안 방패를 들어 앞쪽 공격을 막는다**(아래 "무기" 참고). E는 공격하지 않는다.
- **공격 키**: 기본 **SPACE**. 장착한 무기로 공격한다(검/방패는 한 번 치기, **화염방사기는 누르고 있는 동안** 불을 뿜음). 휴대폰에는 **화면의 ⚔ 버튼**이 있다(무기를 끼고 있을 때만 보이고, 공격 키와 똑같이 동작).
- **벽과 맞았을 때(v45)**: 적에게 맞아 밀려나는 동안은 벽을 통과하고, 다 밀려났는데 벽 안이면 방 안쪽으로 튕겨 나온다(`player.wallPass`, `WALL_EJECT_SPEED`). 평소 이동 중에는 벽이 그대로 막는다.
- **대사/글자**: 스토리 화면과 대사창은 글자가 하나씩 나오고(타자 소리: 작고 부드러운 사인파, 크기 `TYPE_BLIP_VOLUME`), 나오는 중에 누르면 한 번에 다 보인다(`TYPE_MS`).
- **스토리 글 위치(v46)**: 게임에 나오는 이야기 글(도입부, 노트/쪽지/서류/일지/기록, 혼잣말, 결말)은 모두 **`js/01b-story-text.js` 한 파일**에 있다. 글만 고치고 싶으면 이 파일만 열면 된다.
- **화면 위쪽**: 졸음 스택 바는 가운데 위. 왼쪽 위의 조작 안내 글씨는 없앴다. 관리자 모드일 때만 왼쪽 위에 🛠 버튼(무적 ON/OFF, 아이템 바로 얻기).
- **바라보는 방향(`player.facing`)**: 방향키를 누르는 순간 그 방향으로 바뀐다(충전 시작과 동시에). 검을 휘두르는 방향, 방패로 막는 방향, 화염방사기가 나아가는 방향이 모두 이것이다.
- **인벤토리 키**: 기본 **TAB**. 화면 오른쪽 위 ⚙ 바로 아래의 🎒 버튼으로도 연다. 열려 있는 동안 게임은 멈춘다.
- **키 바꾸기**: 설정(⚙ 또는 ESC) 화면에서 인벤토리 키와 공격 키를 플레이어가 직접 정할 수 있다(브라우저에 저장됨, "기본 키로 되돌리기" 있음). 이동 키(WASD/방향키), E, ESC, Enter는 이미 쓰고 있어서 정할 수 없고, 두 동작에 같은 키도 못 쓴다. (`02b-keybinds.js`)
- **졸음 스택**: 화면 왼쪽 위의 회색 바(숫자 포함, 최대 1000). 차징해서 발사할 때마다 +1, 무기로 공격할 때 검 +1 / 방패 +1 / 화염방사기는 불을 뿜은 시간 0.5초마다 +1, 컴퓨터 미니게임에서 공격에 맞으면 +3. 지금은 줄어드는 방법이 없다. 스택 50마다 풀차징 시간 +0.1초, 무기 공격 간격 +0.2초(느려짐). 750부터 화면이 조금 어두워지고, 1000이 되면 5초 동안 서서히 암전된 뒤 **게임 오버**("처음부터 다시" 버튼). (`12b-sleep.js`)
- **비밀 관리자 모드**: 있음. 방법은 이 문서에 적지 않는다(저장소가 공개일 수 있으므로). 코드의 `submitQuiz` 함수 참고. **삭제하거나 화면에 노출하지 말 것.**

### 맵 구조
- 가로로 긴 방(`ROOM_WIDTH=1600`, `ROOM_HEIGHT=250`). 사방이 핑크 구름 벽.
- 메인 방 3개(방0, 방1, 방2)가 **위/아래 벽의 통로**로 이어진다. 포탈/순간이동이 아니라 실제로 뚫린 통로이다.
  - 위쪽 출구는 오른쪽, 아래쪽 입구는 왼쪽(대각선으로 이어지는 형태).
  - 마지막 방(방2)은 위쪽 문이 없다. **맵 탈출구는 없앴다**(v46, 엔딩과 관련 없음). 엔딩이 일어나는 방법은 아직 정해지지 않았다(`onGameCleared`, `ENDING_SCENES`는 남아 있으나 쓰이지 않음).
- 방을 넘어갈 때는 얼리지 않고, 캐릭터의 실제 이동에 맞춰 이어진다. 히든방을 드나들 때는 원래 맵이 문 쪽부터 서서히 검게 덮이고 되돌아오면 걷힌다. 히든방으로 **들어갈 때**는 검게 덮인 부분 밑으로 히든방이 따라 들어오는 모습이 보이고, 히든방에서 **나올 때**는 나가는 쪽 방이 흐릿하게(블러) 보이다가, 거의 다 나오면 다시 또렷하게 보인다.
- **히든방 4곳**(검은 통로로 연결): 히든방1=방3(강의실, 방0 아래에서), 히든방2=방4·5·6(휴게실, 방1 위쪽 별도 통로에서), 히든방3=방7(작업실), 히든방4=방8(실험 공간). 컨셉은 "기억이 투영된 대학원 연구실"이라 테마별 가구 실루엣이 탑뷰로 반투명하게 겹쳐 보인다(`13b-themes.js`). 좌우 폭은 메인 방보다 훨씬 좁고(`HIDDEN_INSETS`), 안에는 적이 없다. 들어갈 때 카메라는 입구에 잠시 고정되었다가, 입구에서 조금(가로든 세로든) 벗어나면 화면이 튀지 않게 서서히 따라온다. 히든방 안의 물건은 아래 "히든방 연구소" 참고.
- **문 연결 표(`DOOR_LINKS`, `10-rooms.js`)**: 방 사이 통로는 "방 a의 위쪽 통로 x ↔ 방 b의 아래쪽 통로 x" 표 하나로 정한다(위로 나가면 b의 아래 통로로 나오고, b의 아래 통로로 내려가면 a의 위쪽 통로로 나옴). 한 방에 통로가 여러 개 있어도 된다. `topDoors`/`bottomDoors`가 표에서 목록을 만들고, 이동 판정(`resolveTop/BottomCrossing`), 장애물 배치, 벽 그리기가 모두 이 목록을 쓴다.
  - 방0 위(1380) ↔ 방1 아래(220), 방1 위(1380) ↔ 방2 아래(220), 방0 아래(800) ↔ 히든방1 위(800)
  - 방1 위(500) ↔ 히든방2의 방4 아래(오른쪽 끝)
  - **히든방2(방 4·5·6)는 예전 폭의 70%(756)** 로 줄였다. 방4↔방5, 방5↔방6 사이에는 **끝 통로 + 가운데 지름길** 두 개씩 있다(방4 위: 왼쪽 끝·가운데 / 방5 위: 오른쪽 끝·가운데). 통로 위치는 `H2_DOOR_L/M/R`(`03-world-player.js`).
  - **히든방2의 맨 위 방(방6) 왼쪽 끝 위 통로 ↔ 히든방3(방7) 아래 통로**, **히든방3 위 통로 ↔ 히든방4(방8) 아래 통로**. 히든방3→2로 내려가는 길이 "자연스러운" 연결이다. (순간이동 연출은 아직 없음)

### 적과 장애물 (맵 배치는 랜덤이 아닌 **고정 패턴**)
- 이동하는 원형 적(빨강), 투척 적(보라, 자기 기준 랜덤 방향으로 포물선 투사체. 투사체는 벽에 닿아야 사라짐), 바닥을 점프하며 좌우로도 움직이는 적(방1부터 등장).
- 벽 장애물: 문을 제외한 벽 전체를 따라 이어지는 납작한 띠. 방 맨 앞 2개는 제외(시작하자마자 연쇄 충돌 방지). 맞으면 같은 벽 쪽으로 붙듯이 튕겨서 연쇄 충돌이 길게 이어진다.
- 맵 가운데: 맞으면 튕기는 돌 오브젝트 하나(그대로), 그리고 **슬라롬 장애물**: 메인 방(방0·1·2)에 **위에서 내려온 구름 기둥과 아래에서 올라온 구름 기둥이 번갈아** 서 있어서 위/아래로 번갈아 빈틈(약 100px)으로 지나가야 한다. 피격은 없고 막기만 한다(`centerBlock`을 쌓아서 만듦). 시작 지점과 문 앞은 비워 둔다. 모양은 `SLALOM_*` 숫자(`10-rooms.js`)로 조절. (예전의 가운데 `centerBlock` 한 줄은 이것으로 대체됨)
- 피격 시 넉백은 오른쪽으로는 가지 않고 항상 왼쪽으로 튕긴다. 맞은 뒤 같은 방향으로 이어서 맞으면 튕기던 방향으로 한 번 더 가속된다(콤보).
- 방0(첫 방)은 적 간격을 넓혀서 밀도를 낮췄다.

- **빨간 적(`enemy`)의 모양(v46)**: 보라색 적 그림을 빨갛게 칠하고 머리를 뺀 작은 몸통(`assets/enemy_red.png`)에 붉은 빛이 일렁이며 돈다. 충돌 반지름은 보라색 적보다 작다(13). 첫 번째 미니게임의 빨간 적도 같은 그림.

### 튜토리얼 상자 (방0, 왼쪽 아래)
- 상자의 x좌표(`TUTORIAL_BOX_X`)와 플레이어가 처음 서는 x(`PLAYER_START_X`)는 같다. 처음엔 아래쪽 키만 열려 있으므로, 아래로만 내려가면 상자를 만난다.
- 상자가 멀리서 보이면 화면이 상자 쪽으로 확대됐다가 원래대로 돌아오면서 "저 상자는 뭐지?" 대사가 나온다.
- 상호작용 키 없이 닿기만 하면 자동으로 열리고, "왠지... 방향키를 해금할 수 있을 것 같은 느낌이 든다...!" 대사와 함께 이후부터 잠긴 방향키의 문제가 열린다.

### 단서 시스템 (임시 버전)
1. **모든 단서가 미니게임을 하는 것은 아니다.** 단서 오브젝트의 `game` 값이 있는 단서만 미니게임을 한다. **지금은 히든방1 가운데의 첫 단서만 미니게임(`game: 'lanes'`)** 이고, 히든방2(방5)의 단서는 `game`이 없어서 **E를 누르면 미니게임 없이 바로 얻는다**(안내 글에 정답이 보임). 다른 단서에도 미니게임을 붙이려면 그 단서에 `game: 'lanes'` / `'circle'` / `'compute'`를 적으면 된다(`10-rooms.js`). **히든방3(방7)의 컴퓨터는 `game: 'compute'`** 이다.
2. 미니게임이 있는 단서에서 E를 누르면 배경이 민트색으로 바뀌는 연출 후 **단서방 미니게임**이 시작된다. 둘 다 **한 번 피할 때마다 정답 힌트 글자가 하나씩 공개**되고(맞아도 페널티는 아직 없음), 글자를 다 모으면 자동으로 끝난다.
   - **`lanes`(첫 번째, 지금 히든방1에서 쓰는 것)**: 플레이어는 화면 고정 위치에서 **위/아래 2칸(레인)만** 오가며(차징 없는 일반 이동), 오른쪽에서 왼쪽으로 달려오는 적을 피한다. (`09-clue-game.js`)
   - **`circle`(두 번째, 지금은 어떤 단서에도 연결 안 됨)**: **원형 경기장 안**에서 가운데의 **보라색 몬스터**가 쏘는 공격을 피한다. 이동은 본 게임처럼 **차징 이동**(4방향 모두, 방향 잠금과 상관없음)이고 원의 가장자리에서는 약하게 튕긴다. 공격은 ① 사방으로 퍼지는 탄 ② 플레이어를 노리는 세 갈래 탄(조준선이 마지막에 빨갛게 고정), 공격 전에는 예고가 보인다. 한 번의 공격에서 날아간 탄이 모두 사라질 때까지 안 맞으면 "피했다". 차징할 때마다 졸음 스택이 오른다. (`09b-clue-game-circle.js`, 난이도 숫자는 파일 맨 위 `CIRCLE_*`)
   - **`compute`(세 번째, 히든방3의 컴퓨터)**: 화면 **왼쪽**에서는 보라색 몬스터의 공격(사방 탄 / 조준 탄)을 **차징 이동으로 피하고**(사각형 구역, 가장자리에서 튕김), **오른쪽 컴퓨터 화면**에는 **객관식 계산 문제**가 나온다. 답은 **숫자 키 1~4 또는 보기를 누르기**. **맞힐 때마다 정답 힌트 글자가 하나씩 공개**되고(`clueGameDodges++`), 글자를 다 모으면(정답 글자 수만큼) 끝난다. 임시 규칙(내가 정함): **틀리면 몬스터 공격이 곧바로 한 번 터지고, 공격에 맞으면 졸음 +3**. 끝내면 단서(메모)와 함께 **부품3**(`reward`)을 처음 한 번만 얻는다. 문제는 임시(덧셈/뺄셈/곱셈)이고 **`generateComputeQuestion()` 하나만 고치면 바뀐다**. (`09c-clue-game-compute.js`, 새 `gameState 'clueGameCompute'`)
3. 단서를 얻으면 인벤토리에 📝(메모)가 들어온다. **정답 입력은 그 단서를 쓰기로 정해진 방으로 넘어갈 때** 뜨는 창에서 한다(단서 오브젝트의 `useAtRoom`): **첫 단서(히든방1)는 2번째 방(방1)으로 넘어갈 때, 히든방2의 단서는 방2로 넘어갈 때, 히든방3 컴퓨터의 단서는 히든방4(방8)로 넘어갈 때.** 맞히면 메모가 소모되고 단서가 해결된다. 같은 단서를 또 얻어도 메모는 늘지 않는다.
4. 정답은 단서 오브젝트의 `answer`(지금은 임시값: 첫 단서 `졸음신호`, 두 번째 `꿈속열쇠`, 컴퓨터 `전원버튼`).

### 히든방 연구소 (임시 도형 버전, 그림은 나중에)
- **(스토리 규칙)** 실험이라는 비밀은 숨겨야 한다. 앞쪽 글/대사에는 "실험·피험자·감시자의 정체·해치지 않아도 된다"를 쓰지 않고, 히든방4의 실험 기록과 결말에서 밝힌다. 초반 설정은 "과제 마감 전에 얼른 잠에서 깨야 한다".
- **■■ 재료와 아이템(v47)**: 📃 찢어진 쪽지(히든방1 쪽지를 읽고 닫으면 얻음), 🧪 용기(히든방1), 💉 약품(히든방3 바닥), 🔸 전리품(적을 쓰러뜨리면 인벤토리에 바로 들어옴), 💊 ■■(제작 결과, 먹으면 폭주 → 노멀 B), 📜 낡은 메모(히든방2 방5, "■■를 먹으면 탈출할 수 있을 것이다"). 철 조각은 이제 쓸 곳이 없다. 제작 탭에는 찢어진 쪽지를 가졌을 때 ■■ 카드가 나타난다(서류 뭉치와 별개).
- **엔딩 화면(v47)**: 결말 장면 → 카드 획득 → "처음부터 다시" 화면. 트루/히든 엔딩은 얻는 방법이 아직 없다.
- **그림 소품(v48)**: 컴퓨터(히든방3), 서랍/서류 뭉치(히든방2 방4)는 사람이 그린 도트 그림으로 그려진다(`assets/prop_*.png`). 서류 뭉치 아이템의 인벤토리 아이콘은 `assets/icon_docs.png`. 히든방4(실험 공간)에는 **장갑, 실험 안경, 화학 기계, 스위치**가 장식 소품(`type 'prop'`)으로 놓여 있고, E로 살펴보면 한 줄 설명(`PROP_TEXTS`)만 나온다. 오브젝트에 `sprite: '이름'`을 적으면 그 그림으로 그려진다(이름은 `03b-sprites.js`의 `SPRITE_FILES`).
- **히든방1 (강의실)**: 가운데 아래에 첫 단서(미니게임), **왼쪽 구석에 연구 노트와 그 옆의 찢어진 쪽지**, **오른쪽 구석에 용기**, 왼쪽 쪽에 **부품1**. (예전에 임시로 놓았던 무기 3종은 **지웠다**: 무기는 이제 부품으로 만든다.)
  - 연구 노트: E로 읽으면 노트가 화면에 뜨고, 쪽을 넘기는 느낌의 애니메이션과 함께 여러 쪽을 볼 수 있다(◀ ▶ 버튼, 방향키/Space, 종이 클릭). 내용은 아직 **임시 문구**이고 연구소 이야기로 바꿀 예정(`07b-reader.js`의 `NOTEBOOK_PAGES`).
  - 찢어진 쪽지: 한 장짜리. "■■ 만드는 방법 1. 재료를 혼합할 용기를 구한다. 2. 철 조각을 구한다. 3. 이 쪽지를 넣는다. 4. ■■■를 만들어 넣는다. 5. 절대" 에서 끝나고 이후는 찢어져 있다(`TORN_NOTE_PAGES`). **마지막 줄 "5. 절대"는 찢어진 가장자리에 걸려 글자 아랫부분이 반쯤 잘려 보인다**(`style.css`의 `#readerBook.paper`). 쪽지의 "넣는다"를 실제로 하는 조합 시스템은 아직 없다.

### 무기와 적 체력
- 적(이동형/투척형/점프형)의 체력은 **10**(`ENEMY_MAX_HP`)이고 0이 되면 사라진다. 체력이 깎인 적만 머리 위에 체력 막대가 보인다. 벽 장애물·돌·기둥은 맞아도 변화 없음. 맞은 적은 하얗게 번쩍이며 밀려났다가 서서히 원래 움직임으로 돌아온다.
- 무기는 **3종**(수치는 `11b-weapons.js`의 `WEAPONS`): **검, 방패, 화염방사기**(작살은 없앴다). 무기는 **부품으로 만든다**(아래 "인벤토리"의 제작 탭). **공격 키(기본 SPACE)** 또는 화면 ⚔ 버튼으로 바라보는 방향으로 공격하고, 졸음이 쌓일수록 공격 간격이 길어진다.

| 무기 | 데미지 | 공격 간격 | 졸음 스택 | 특징 |
|---|---|---|---|---|
| 🗡️ 검 | 3 | 1초 | +1 | 앞쪽 가까운 범위를 벤다. 적을 밀어냄. **호를 그리며 휘두르는 칼날과 꼬리 잔상**(공격할 때마다 휘두르는 방향이 번갈아 바뀜). |
| 🛡️ 방패 | 1 (치기) | 1초 | +1 (치기) | **E를 누르고 있는 동안 바라보는 방향 앞쪽 약 120도에서 오는 공격(적 몸 접촉, 던지는 공, 벽 장애물)만 막는다.** 뒤나 옆에서 오면 그냥 맞는다. 공격 키로 치면 앞으로 쑥 내밀었다 돌아오며 충격 효과(적을 맞추면 더 크게). 상호작용할 것이 가까이 있으면 E는 상호작용이 우선. |
| 🔥 화염방사기 | 0.25초마다 1 (임시) | (누르는 동안) | 0.5초마다 +1 | **공격 키를 누르는 동안 바라보는 방향으로 차징 없이 가속해서 나아가며**(최고 속도 풀차징과 비슷) 앞쪽 부채꼴(약 70도, 58px)을 태운다. 연료는 **약 1.2초**(`FLAME_BURN_RATE`), 중간에 떼도 되고, 쓰지 않으면 **5초에 걸쳐 가득 찬다**(연료가 0.25초 아래면 다시 켤 수 없음). 이동 거리는 짧다(최고 속도 약 2.2, `FLAME_ACCEL`). 연료 게이지는 화면 왼쪽 아래 무기 표시에 주황색으로 보인다. 맞으면 꺼진다. |

- 모든 무기는 적의 **투사체(던지는 공)도 부술 수 있다.** 투사체를 부수는 것은 "적을 죽인 것"으로 세지 않는다. 적이 무기로 죽으면 `gameStats.kills`가 오른다(스토리 분기용).
- 방패 막기 범위는 `SHIELD_BLOCK_COS`(0.5 = 60도), 화염방사기 수치는 `FLAME_*`(`11b-weapons.js` 맨 위)에서 고친다. 막는 판정은 `shieldBlocks(공격이 오는 x, y)`.
- **망치는 무기가 아니다.** 금이 간 상자를 부수는 도구이다.

### 그림(스프라이트)
- 그림 파일은 `assets/` 폴더에 있고, 이름과 쓰임은 `03b-sprites.js`의 `SPRITE_FILES`에 적혀 있다. 같은 이름의 파일을 바꿔 끼우면 게임 그림이 바뀐다(그림의 **중심**을 기준으로 그려지므로 크기가 조금 달라도 됨).

| 파일 | 크기(칸) | 쓰임 |
|---|---|---|
| `player_idle.png` | 36×27 | 주인공: 가만히 있을 때 (작은 구름 위에서 자는 모습, 아주 살짝 둥실) |
| `player_charge1.png` | 38×30 | 충전 20% 이상일 때 / 발사 직후 / 빠르게 날아가는 동안 (구름이 몽실하게 커짐) |
| `player_charge2.png` | 48×38 | 충전 70% 이상일 때 / 발사 직후 잠깐 (구름이 크게 부풀음) |
| `afterimage_a.png`, `afterimage_b.png` | 26×23, 26×21 | 충전 후 남는 잔상 구름(납작한 원): 발사한 자리에 큰 것, 날아가는 길에 작은 것들이 서서히 사라짐 |

- **그림체는 "우리 게임스럽게" 단순화한 상태**: 색을 14가지 안팎으로 줄이고, 주인공의 얼굴은 **눈만**(감은 눈 두 개) 있다. 이 방향(단순한 도트)을 유지할 것. 연구실을 탑뷰로 바꿀 때 주인공도 탑뷰로 새로 그릴 예정(제미나이와 작업).
- 주인공은 왼쪽을 보고 충전/이동하면 그림이 좌우로 뒤집힌다. 맞으면 붉게 깜빡인다. **충전 중/충전 후에는 흔들리지 않는다**(가만히 있을 때만 `PLAYER_IDLE_BOB`로 1칸 정도 천천히 둥실, `false`로 바꾸면 멈춤). 주인공 그림은 첫/두 번째 미니게임에서도 같은 것을 쓴다.
- **그림을 못 불러오거나 파일이 없으면 예전의 네모 모양으로 대신 그려진다**(게임은 멈추지 않음). 이때 화면 아래에 어떤 파일이 없는지 알려주는 빨간 오류 상자가 뜬다.
- **오류 안내 상자**(`index.html`의 `errorBox`): 파일을 못 불러왔을 때, 코드 오류가 났을 때(게임 루프는 `14-main.js`에서 멈추고 오류를 알림) 원인을 보여준다. 일부 파일만 새 버전으로 덮어써서 서로 안 맞을 때 "OO is not defined (파일, 줄)"로 나타난다. 누르면 닫힌다.
- 이동용 충돌 범위(히트박스)는 그림보다 작다(주인공 14×18). 그림은 보이는 모습일 뿐 충돌 범위는 코드의 숫자(`player.w/h`, `en.r`)다.
- `assets/source/`에는 배경만 지운 **큰 원본**(투명 PNG)이 있다. 다른 크기로 다시 줄이거나 그림을 개선할 때 쓴다.
- **새 그림을 만들 때 주의**: AI가 그린 그림은 투명 배경이 아니라 **회색 체크무늬 무늬가 그림에 박혀서** 나오는 경우가 많다. 진짜 투명 배경 PNG로 만들어 넣고, 게임 크기로 줄여서(얼굴 같은 작은 부분이 뭉개지지 않게 확인) 넣는다. 도트 한 칸이 화면 2×2 픽셀로 커져 보인다.

### 인벤토리 (`07-inventory-interact.js`, `07c-inventory-ui.js`)
- **TAB(기본) 또는 오른쪽 위 🎒 버튼**으로 열고 닫는다(ESC로도 닫힘). 열려 있는 동안 게임이 멈춘다. 이전의 화면 왼쪽 아래 아이템 바는 없어졌고, 그 자리에는 **장착한 무기와 공격 대기 시간**만 작게 보인다.
- **아이템은 하나하나 따로 칸**에 들어간다(같은 아이템이 2개면 칸 2개). 칸을 누르면 오른쪽에 이름/설명이 보인다. 무기는 [장착]/[해제] 버튼이 있다(장착은 한 번에 하나).
- 아이템은 `ITEM_DEFS`에 정의돼 있다(아이콘/이름/종류/설명): 📝 단서 메모, 🔑 열쇠(아직 쓸 곳 없음), 🧪 용기, 🔩 철 조각, 🔨 망치, 💥 부서진 망치, 🗡️ 검, 🛡️ 방패, 🔥 화염방사기, ⚙️🔧🔋💡 부품1~4. `addItem(type)`으로 넣고 `useItem(type)`으로 1개 소모.
- **엔딩 카드** 탭: 엔딩 4장(노멀 A, 노멀 B, 트루, 히든)이 칸으로 보이고, **얻지 못한 카드는 빈 칸**이다. 엔딩이 일어나는 곳에서 `unlockEnding('normalA')`처럼 부르면 카드가 채워지고 브라우저에 저장된다(지금은 얻는 조건이 코드에 없음). 카드 글은 `ENDINGS`(`07c-inventory-ui.js`)에 있고 임시다.
- **제작 탭**: 무기 제작법이 **항상** 보인다(스토리의 "무기 제작법 서류 뭉치" 역할을 대신함). **서류 뭉치 아이템(히든방2 방4의 서류 뭉치를 읽고 닫으면 얻음)이 없으면 제작 탭은 ???로 보이고 만들 수 없다.** 서류를 얻으면 부품을 가졌는지 ✔로 보이고 [만들기] 버튼으로 만든다. **검 = 부품1+2+3, 방패 = 부품1+3+4, 화염방사기 = 부품1+2+4.** 부품1은 모든 무기에 들어가는 기본 부품이다(내가 해석한 것 → 사람이 확인). 부품이 하나씩밖에 없어서 한 무기를 만들면 부품이 소모돼 다른 무기는 못 만든다. 만든 무기는 아직 장착한 무기가 없으면 자동으로 장착된다. 제작법은 `RECIPES`(`07c-inventory-ui.js`). 실제 서류 글(스토리)은 아직 없다.

## 5. GitHub 협업 방식 (예정)

- 저장소에 올린 뒤 **Claude와 Gemini를 번갈아** 쓰며 개발한다. 이 채팅의 AI는 저장소에 직접 push할 수 없으므로, 사람이 파일을 복사/업로드해서 전달한다.
- **저장소 구조**
  ```
  index.html      화면 구조(HTML)
  style.css       스타일
  js/             게임 로직 (01~14번 파일과 02b, 03b, 07b, 07c, 07d, 09b, 09c, 11b, 12b, 13b, 위 3번 표 참고)
  assets/         게임 그림(PNG)
  archive/        안 쓰는 옛 코드, v38 단일 파일 백업
  README.md       처음 보는 사람을 위한 사용법(실행, GitHub 올리기, Netlify)
  DESIGN.md       이 문서 (기준 문서, 잘 안 바뀜)
  HANDOFF.md      AI끼리 작업 내용을 주고받는 공유 파일 (자주 바뀜, 아래 6번 참고)
  CHANGELOG.md    버전별 변경 기록
  ```
- **충돌을 줄이는 요령**: 파일이 나뉘어 있으니 AI마다 **담당 파일을 정해서** 작업한다. 예: Claude는 `09-clue-game.js`, Gemini는 `13-render.js`. 두 AI가 같은 파일을 동시에 고치지 않도록 `HANDOFF.md`의 "현재 작업 중" 표에 담당 파일을 적는다. 한 기능이 여러 파일에 걸치면(예: 새 적) 한 AI가 끝까지 맡는다.
- **브랜치**: `main`은 항상 잘 돌아가는 버전만 둔다. Claude 작업은 `claude`, Gemini 작업은 `gemini` 브랜치에서 하고, 확인 후 Pull Request로 합친다.
- **규칙**
  1. 작업 시작 전에 이 문서를 먼저 읽는다.
  2. 한 번에 한 가지 기능만 맡기고, 같은 기능을 두 AI가 동시에 고치지 않는다.
  3. "결정된 사항"(2번 항목)을 바꾸려면 먼저 사람에게 확인한다.
  4. 변경 후에는 이 문서의 2번 항목과 `CHANGELOG.md`를 갱신한다.
  5. 코드 주석과 설명은 한국어로, 초보자도 이해할 수 있게 쓴다.
  6. 작업이 끝나면 브라우저에서 실제로 돌려 보고 커밋한다(문제가 생기면 이전 커밋으로 되돌릴 수 있게).
  7. 관리자 모드 코드와 같은 비밀 기능은 문서와 화면에 드러내지 않는다.
  8. 작업을 시작하기 전에 `HANDOFF.md`를 읽고, 끝나면 그 파일에 기록을 남긴다(6번 참고).

## 6. AI끼리 소통하는 공유 파일: `HANDOFF.md`

AI들은 서로 직접 대화할 수 없습니다. 대신 **저장소 안의 `HANDOFF.md` 파일을 우편함처럼** 써서 작업 내용을 주고받습니다. 사람이 이 파일을 각 AI에게 전달해 주면 됩니다.

**역할 구분**
- `DESIGN.md` = 게임의 기준(무엇을 만드는가). 거의 안 바뀐다.
- `HANDOFF.md` = 작업 이어받기 메모(누가 무엇을 했고, 다음에 무엇을 하는가). 작업할 때마다 바뀐다.

**쓰는 순서**
1. 작업을 시작할 때 `HANDOFF.md`를 읽는다. 특히 맨 위의 "현재 작업 중"과 가장 최근 기록, 그리고 나에게 온 질문/부탁을 확인한다.
2. 내가 맡을 작업을 "현재 작업 중" 표에 적는다(다른 AI가 같은 곳을 건드리지 않게).
3. 작업이 끝나면 **기록을 맨 위에 새로 추가**한다(최신이 위). 형식은 `HANDOFF.md`에 있는 양식을 그대로 쓴다.
4. 다른 AI에게 묻고 싶은 것이나 부탁은 기록 안의 "다음 AI에게" 칸에 적고, 답은 그 기록 바로 아래에 "답변:"으로 이어서 쓴다.
5. 끝났으면 "현재 작업 중" 표에서 내 줄을 지운다.

**기록에 꼭 들어갈 것**
- 날짜 / 작성자(Claude, Gemini, 사람) / 브랜치 / 기준 버전
- 한 일 (어느 파일, 어느 함수를 바꿨는지)
- 아직 안 끝났거나 알려진 문제
- 다음 AI에게 부탁·질문
- 주의사항 (건드리면 깨지는 부분 등)

**사람이 할 일**
- 두 AI 사이의 전달자입니다. 한쪽 AI의 작업이 끝나면 최신 코드와 `HANDOFF.md`를 다른 AI에게 보여 주세요.
- AI의 제안이 서로 다를 때는 사람이 정합니다. 결정한 내용은 `HANDOFF.md`의 "사람 메모"에 적고, 게임의 기준이 바뀌었다면 `DESIGN.md`도 고칩니다.
